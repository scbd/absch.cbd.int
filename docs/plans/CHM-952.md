# CHM-952: BCH/ABSCH/CHM homepage "recent records" overlapping text

> Bug. Labels: ABSCH, BCH, CHM, bch — reported/suspected across all three
> clearinghouse deployments. No linked PRD/ADR; this is a CSS regression fix.
> Screenshot attached to the ticket was an inaccessible temporary Atlassian
> media blob (`blob:https://media.staging.atl-paas.net/...`, dimensions
> 1888×1093) — could not be viewed. Diagnosis below is from static code
> inspection + git blame, not a visual confirmation of the screenshot. See
> **Open assumption** below.

## Intent

Stop the homepage "recent records" card text (title / summary / metadata
badges) from visually overlapping, without breaking the layout at any other
viewport width, locale, or clearinghouse.

## Root cause (evidence-based)

The homepage "recent records" section is one shared Vue 3 component,
`app/components/common/homepage-records.vue`, hosted as an AngularJS
directive (`ng-vue="exportVueComponent"`) in all three clearinghouse home
views:

- `app/views/home/index.html:150,160` (ABSCH)
- `app/views/home/bch.html:151,161` (BCH)
- `app/views/home/chm.html:153,163` (CHM)

— both for the "national records" section (`type="national"`) and the
"reference records" section (`type="reference"`). Its CSS lives in one
shared stylesheet, `app/css/template.css` (loaded by all three clearinghouse
entry templates — `app/templates/{absch,bch,chm}/index.ejs:28` — before each
clearinghouse's own override file at line 29). **No per-clearinghouse
override exists** for any of the classes involved (`record-callout*`,
`country-records-sub-options`, `date-badge`, `record-summary-text*`,
`w-sm-100` — confirmed absent from `app/css/{abs,bch,chm}/template.css`).
So this is a single shared bug, not three separate ones.

Each record card (`homepage-records.vue:8-25` and `:30-47`, structurally
identical for both the first 4 records and the `d-lg-block`-only next 4) is:

```html
<div class="d-flex position-relative record-callout record-callout-national …">
  …
  <div class="flex-grow-1">
    <span class="badge position-absolute top-0 end-0 date-badge">…date…</span>
    <span><a class="… stretched-link …">{{record.rec_title}}</a></span>
    <p :class="… ? 'record-summary-text' : 'record-summary-text-single-line'">
      <span v-if="record.rec_summary">{{ record.rec_summary }}</span>
    </p>
    <div style="bottom:5px;" class="w-sm-100 position-absolute">  <!-- 2nd block: class="country-records-sub-options" -->
      … schema badge, country badge, unique-id badge …
    </div>
  </div>
</div>
```

- `.record-callout` is `position: relative`. The title (`.record-callout
  span a`) and summary (`.record-summary-text`) are normal in-flow content,
  each clamped with `-webkit-line-clamp` (`app/css/template.css:415-428`).
- The bottom metadata row (schema/country/unique-ID badges) is pulled out of
  flow: `position: absolute; bottom: 5px` (inline style on the first block,
  `app/css/template.css:536-541` `.country-records-sub-options` on the
  second). An out-of-flow element **never contributes to its positioned
  ancestor's height** — nothing reserves vertical space for this row.
- `.record-callout-national` (`app/css/template.css:319-322`) currently sets
  a **fixed `height: 7.8rem`** (124.8px) — not `min-height`. Its sibling
  `.record-callout-reference` (`:323-326`) uses `min-height: 7.5rem`. Because
  `homepage-records.vue:8` applies `record-callout-national` **unconditionally**
  on every card (reference cards get `record-callout-reference` bolted on
  *in addition to*, not instead of, `record-callout-national` — likely a
  copy/paste leftover from before the type split), and `height` + `min-height`
  both apply with `min-height` only winning if it's larger, the fixed
  124.8px box governs **both** the national and reference sections.
- Content budget inside that fixed box: 124.8px − 32px (`p-3` padding, both
  sides) = **92.8px** for title + summary. Title is line-clamped to 2 lines
  and summary to 2 lines (`record.rec_countryName.length < 21`) — at the
  default 1rem/1.5 line-height body text this is comfortably ≥ 96–112px once
  the `<p>`'s default bottom margin is included, i.e. it **exceeds the fixed
  box's content budget**. Since the box height is fixed (not min-height), the
  overflowing text is not clipped, it renders past the box — landing exactly
  where the absolutely-positioned metadata badge row is pinned (`bottom:
  5px`), which paints after the text in DOM order and so visually overlaps
  it. This is "recent records text overlapping."

**Git-confirmed regression.** `git log -L 310,330:app/css/template.css`
shows commit `51ebfcf83` ("Merge Vue3 implementation (#1199)") changed
`.record-callout-national` from `min-height: 7.5rem` (matching
`.record-callout-reference`, which still has it) to `height: 7.8rem`. That
single property change is the most direct, evidenced cause: before it,
national and reference cards behaved identically and (per absence of any
older overlap ticket) did not overlap.

### Breakpoint range

- **`@media (max-width: 768px)`** (`app/css/template.css:493-521`) already
  overrides `.record-callout-national` to `min-height: 130px` and drops both
  title and summary to a 1-line clamp — mobile is the one tier someone
  already patched. This materially reduces text volume and lets the box
  grow, so mobile is **low risk / likely not reproducing**, but should still
  be checked (see Verification) since the out-of-flow badge row is still
  absolutely positioned there too.
- **`@media (max-width: 1200px)`** (`:560-564`) drops `.record-summary-text`
  (but *not* the title — the paired selector `.record-callout h6 a` is dead
  code, there is no `<h6>` inside `.record-callout`; the title lives in a
  `<span><a>`) to a 1-line clamp. So the 769px–1200px band has 2-line title +
  1-line summary — some risk, less than the top tier.
- **`≥ 1201px`** has the full 2-line title + 2-line summary budget against
  the same fixed 124.8px box — **highest risk band**, and consistent with
  the ticket screenshot's recorded dimensions (1888×1093 — a wide desktop
  capture).
- **Net: reproduces for viewport width ≥ 769px**, worst above 1200px.
  Exact 768px/1200px Bootstrap breakpoints match this codebase's existing
  media queries, not a guess.

### Shared vs. per-clearinghouse

One fix, applied once. The component (`homepage-records.vue`) and the
governing CSS (`app/css/template.css`) are both shared, unforked across
ABSCH/BCH/CHM — confirmed by grepping all three `app/css/<ch>/template.css`
override files for every class name involved and finding no matches. No
clearinghouse-specific branching is needed or should be added.

### Migration-ratchet check

`homepage-records.vue` is **already a Vue 3 SFC** (`<script setup>`, single
root `<div>`) — it is not AngularJS-owned code, so the ratchet's "feature
work that touches an ng view should migrate it to Vue rather than patch it"
does not apply here: there is no ng view to migrate. The fix touches only
`app/css/template.css` (framework-neutral) and optionally the Vue
component's own template/scoped style — **no AngularJS home view file
(`index.html`/`bch.html`/`chm.html`) needs to change**. This is a decision
point worth stating explicitly (per AGENTS.md) precisely because the answer
turned out to be "not applicable" rather than something to silently assume.

### Open assumption (needs confirmation)

I could not view the ticket's screenshot (inaccessible temp Atlassian media
blob). The diagnosis above is built entirely from static code inspection —
line-clamp/box-height arithmetic and a git-blamed regression commit that
match "overlapping text" and the screenshot's recorded desktop dimensions —
not from seeing the actual overlap. **Before implementing, reproduce this
locally** (`yarn dev`, resize to ≥1201px, ≥769px, and ≤768px, with real
homepage record data that has long titles/summaries) and confirm the
overlap matches this description before committing to a fix. If the
reproduction looks different (e.g. overlap is between the top-right
`date-badge` and the title instead, or is an entirely different section of
the homepage), stop and re-diagnose rather than forcing this fix.

## Approach — decided: structural flexbox fix

Two options were weighed (minimal one-line CSS revert vs. a structural
flexbox fix); a human reviewed the tradeoff and chose the structural fix,
because this codebase ships 6 locales (including French and Russian, which
commonly run 20–30% longer than English) and a minimal revert only narrows
the reproduction window rather than closing the underlying "out-of-flow
footer doesn't reserve its own space" pattern — it would likely resurface as
a different-locale bug report later.

**Reserve space for the footer row with flexbox (structural).**
Make the card's content column a flex column and let the metadata badge row
push itself to the bottom via margin instead of being pulled out of flow:
- In `homepage-records.vue`, add `d-flex flex-column h-100` to both
  `.flex-grow-1` wrapper divs (`:12` and `:34`).
- Replace `style="bottom:5px;" class="w-sm-100 position-absolute"` (`:18`)
  and `class="country-records-sub-options"` (`:40`) with a plain `mt-auto`
  (Bootstrap utility, already used elsewhere in this codebase, e.g.
  `app/components/bulk-import/components/bulk-import-banner.vue`) — no new
  CSS needed.
- `app/css/template.css:319-322` still needs `min-height` instead of
  `height` (undoes commit `51ebfcf83`'s property change) so the card can grow
  past 7.8rem for unusually long content instead of clipping.
- `.country-records-sub-options` (`app/css/template.css:536-541`) becomes
  dead CSS once nothing references it — remove it; since this fix is what
  orphans it, removing it is in scope (it's *this change's* orphan, not a
  pre-existing one, per the surgical-changes guardrail).
- The `w-sm-100` class (used only on `:18`) does not exist in any CSS file
  in this repo — it is currently a no-op. Dropping it as part of the `mt-auto`
  swap is this change's own cleanup, not unrelated tidying.
- This eliminates the entire class of "out-of-flow footer overlaps
  unclamped-height text" bugs regardless of exact title/summary length or
  locale, at the cost of touching the Vue template (not just CSS) — still a
  single shared component, single fix, no framework/ratchet issue (see
  above).

## Behavior

- No visible change to card layout when title/summary text is short enough
  to already fit (the common case) — only the failure mode for longer text
  changes (grows/reserves space instead of overlapping).
- No API, routing, or data changes. `app/api/` is untouched — this is a
  pure CSS/template layout fix, per AGENTS.md's "all HTTP calls live in
  app/api/" note, not applicable here since nothing here talks to the API
  layer.
- Applies identically to ABSCH, BCH, and CHM homepages, and to both the
  "national records" and "reference records" sections on each.

## Tests

No automated test suite exists in this repo yet (`vitest` not installed, no
spec files — per AGENTS.md/Tests). This is a pure CSS/layout bug with no new
service or filter being inverted, so the migration ratchet's "ships with
vitest tests" clause does not apply (that clause is for newly-inverted
services/filters, not CSS fixes). Verification is manual:

1. `yarn dev` (English locale, dev build).
2. Load each clearinghouse homepage that renders `homepage-records.vue`
   (`CLEARINGHOUSE=ABS` → `/`, `CLEARINGHOUSE=BCH` → `/`, `CLEARINGHOUSE=CHM`
   → `/`) — set `CLEARINGHOUSE`/`CLEARINGHOUSE_HOST` per AGENTS.md's
   "Commands" section and restart `node server.js` between clearinghouses,
   since the env var is read at server start.
3. At each of: ~1920px (≥1201px tier), ~1024px (769–1200px tier), ~768px and
   ~375px (≤768px tier), scroll to "Recently added national records" and
   "Recently added reference records" and confirm:
   - Title, summary text, and the bottom schema/country/ID badge row never
     visually overlap, for both short-text and long-text records (may need
     to eyeball live Solr data or temporarily stub `recordList` with a
     long-title/long-summary fixture to force the worst case).
   - Cards in a row stay equal height / don't visually jump between
     adjacent cards.
   - The top-right `date-badge` still doesn't collide with the title.
4. Spot-check a non-English locale with typically longer strings (`fr` or
   `ru` per `yarn build`'s locale list) if time allows, since AGENTS.md flags
   locale length as a real risk for this exact clamp/height arithmetic —
   otherwise note it as unverified in the PR.
5. Confirm no fragment/multi-root-node regression was introduced in
   `homepage-records.vue` (still one root `<div>`) — required because this
   component is consumed as an AngularJS directive via `ng-vue`, and
   multi-root Vue components silently break in that bridge (AGENTS.md
   hybrid-layer pitfall).

## Risks

- **Diagnosis is unverified against the actual screenshot** (inaccessible
  media blob) — see *Open assumption* above. Low-medium likelihood of being
  wrong, since the git-blamed regression and line-clamp arithmetic both
  independently point at the same rule, but this is not a substitute for
  seeing the real screenshot or reproducing live.
- **Option A alone may not fully close the bug** for outlier-long text (see
  Option A risk note) — needs explicit manual verification with long-content
  fixtures, not just default/typical Solr data, or the fix may look done
  and still reproduce in production with unlucky record content.
- **RTL (Arabic locale)**: `-webkit-line-clamp` and flexbox `mt-auto` are
  both direction-agnostic, so no RTL-specific breakage is expected, but this
  repo has no existing RTL smoke-test for this component — worth a quick
  visual check if `ar` locale is reachable in dev.
- **`.record-callout-national` being unconditionally applied to reference
  cards** (`homepage-records.vue:8`) looks like a naming leftover from
  before the type split, and is *why* the reference section is affected by
  a rule named "-national" at all. Out of scope to rename/restructure here
  (surgical-changes guardrail) — noted for awareness only, not to be
  "improved" as part of this bug fix.

## Success criteria

1. Manual verification (Tests section) passes at all four viewport tiers,
   on all three `CLEARINGHOUSE` values, with no overlap for both short and
   deliberately-long record title/summary content.
2. `yarn lint` passes on the changed file(s) (`.vue` and `.css`).
3. No AngularJS view file (`app/views/home/*.html`) changed — confirms the
   migration-ratchet decision point above held.
4. Diff is limited to `app/css/template.css` +
   `app/components/common/homepage-records.vue` — no unrelated files
   touched.
