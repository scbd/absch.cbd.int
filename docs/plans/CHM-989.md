> generic `documentInfo` metadata with `{ body: document }`, since the Vue
> component expects the document under `documentInfo.body`), and registering

> other ABS schemas. **Note the schema key is `absLegalFramework`**

> `legalFrameworkOverview` — that wrong key was also caught and fixed in
> `app/app-data/abs/realm-configuration.json`'s `schemas` map (would have
> broken `realm.schemas[schema]` lookups used for menus/dashboards and by
> `record-loader.directive.js` itself), and the directive/file name follows
> `'view-' + snake_case(schema)` (`view-abs-legal-framework`), which is
> generated from the schema, not from the Vue component's own file name.
>
> **Second gotcha, same fix session**: the wrapper directive's template
> initially had `ng-if` on its root `<div>`. Because the directive uses
> `replace: true`, that root gets merged with record-loader's generated
> attributes onto one node, and `ng-if` (high priority, `terminal: true`)
> takes over that node's compilation before the directive's own isolate
> scope exists — so `ng-if`'s expression evaluates against record-loader's
> *outer* scope, not the isolate one. The directive's own scope variable was
> named `shareVueComponent`, which collided with `record-loader.directive.js`'s
> own pre-existing `$scope.shareVueComponent` (used for its unrelated
> share-button feature) — so the guard silently evaluated true against the
> wrong object, and the nested `ng-vue` mount picked up the wrong
> `components` map. Fixed by (1) moving `ng-if` one level below the
> `replace: true` root (onto a child `<div>`, guarding on
> `legalFrameworkOverviewVue`) and (2) renaming the scope variable to
> `legalFrameworkOverviewVue` so it can't collide with record-loader's own
> `shareVueComponent` regardless of scope-chain subtleties. Any future
> `view-*.directive.html` written with `replace: true` should keep `ng-if`
> (or any structural directive) off the template's root element.

## Intent

Build out the two existing stub Vue components into the complete "ABS Legal
Framework Overview" (LFO) submission form and read-only view, matching the
v5 doc content (minus paper-only sections), using the same static
per-field-block approach as every other form in this repo — not a
generic/dynamic question renderer.

## Scope

**In scope (this repo, CHM-989):**
- `edit-legal-framework-overview.vue` — full submission form.
- `legal-framework-overview.vue` — full read-only view (also serves as the
  pre-publish review screen via the existing generic
  `workflow-arrow-buttons` → `<review-form>` wiring).
- `legal-framework-overview.ts` type — expand to the full document shape.
- Translation file — expand with all new keys.
- Missing `/register/LFO/:identifier/edit` route.
- `legalFrameworkOverview` schema registration in `app/app-data/abs/realm-configuration.json`.
- New small FAQ repeater control.
- `AGENTS.md` ratchet wording update.

**Out of scope:**
- The backend C# schema change itself (documented below for CHM-943, but
  implemented in the separate `km` repo, not this one).
- Any dedicated "Review and Publish" page — the generic mechanism already
  covers it.
- Client-side duplicate-jurisdiction validation — enforced backend-only per
  CHM-943 (grilling decision); front end only needs to surface whatever
  validation error the API returns.
- Any menu/dashboard/search-filter wiring beyond the realm-config schema
  registration itself, unless discovered to be required once that entry
  exists (flag as a follow-up if so — out of this plan's field-mapping
  scope to pre-solve every integration point blind).

## Approach

### 1. `AGENTS.md` ratchet wording

Reword:
> No new Vue forms that wrap an ng km-control through the Bridge.

to something like:
> No new AngularJS directives/controllers/components. Bridging *existing*
> ng km-controls into a new Vue form via `v-vue-ng:` is acceptable until
> that control is ported — porting only happens when a form's needs justify
> the cost (see `docs/plans/CHM-989.md` for the reasoning).

Exact wording is a judgment call for whoever implements this — the point is
removing the contradiction with actual practice, not the precise phrasing.

### 2. Realm config schema registration

Add a `legalFrameworkOverview` entry to the `schemas` map in
`app/app-data/abs/realm-configuration.json`, following the exact shape of
neighboring entries (see `measure`, lines 103-130): `type: "national"`,
`title`/`description`/`titlePlural` (multi-locale — **English text is known
from the v5 doc header, "ABS Legal Framework Overview"; the other 5 locale
strings need real translations, not invented ones — flag as an open item,
same handling as any other untranslated string in this repo**), `shortCode:
"LFO"`.

### 3. Routes

Add `/register/LFO/:identifier/edit`, mirroring the MSR pair exactly
(`app/routes/absch.js:76`, same `register_LFO_edit` resolve target already
used by the `/new` route).

### 4. Type (`legal-framework-overview.ts`)

Expand `LegalFrameworkDocument` to the full field set from the mapping table
below (Approach step 6), typed against whatever the equivalent backend
`NrResponse<lstring>` shape resolves to elsewhere in this codebase (check
`app/types/` for an existing `NrResponse`-equivalent type used by other
national-report-style forms before inventing a new one).

### 5. FAQ repeater control

New small component (Vue, native — no ng bridge needed since nothing to
bridge to), modeled directly on `km-link`'s list+modal structure
(`app/components/scbd-angularjs-controls/form-control-directives/km-link.js/html`):
a list of `{ question: lstring, answer: lstring }` entries, "+ Add FAQ"
button opens a small editor (two textboxes, matching Blaise's confirmed
"two textbox" answer), list shows entries with a remove (trash) action per
row, matching `km-link`'s remove UX. Determine at implementation time
whether this is small enough to be a plain Vue component or needs its own
ng directive for Bridge-consistency with the rest of the form — given it's
genuinely new, prefer native Vue per the ratchet's intent (this is the one
control in this form NOT reusing an existing ng directive, so there's no
bridging tension to resolve).
