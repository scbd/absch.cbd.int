# CHM-1003: IRCC bulk update - MAT established needs to be mandatory

> Type: Bug · Jira status when planned: In Review · Component: ABSCH
> Branch: `blaise/bug/CHM-1003-ircc-mat-mandatory` (off `origin/master`)
> Ticket has no description; scope comes from the grilling session (2026-11-05):
> **the IRCC Excel import must behave like the ABS permit edit form** — every
> field the form requires is required in Excel, and a blank is a blocking error.

## Findings

1. **`required: true` in `attributes-map.ts` does not block import.** It only
   (a) draws the `*` on the column header (`bulk-import-modal.vue` `requiredKeys`)
   and (b) is passed to `read-excel-file`, whose blank-cell errors
   `read-sheet.ts` maps to `level: 'warning'`. The modal disables Import only
   on `level === 'error'` (`hasErrors`). So today a blank `language`, `country`,
   `absCNAId`, `dateOfIssuance`, `subjectMatter` or `usage` is **not blocked**
   either — only the contact fields (`CONTACT_REQUIRED_FIELDS`) produce real
   errors, from `validateRows` in `ircc/index.ts`.
2. **Form-required vs Excel (edit-absPermit.html):**

   | Form field | Excel col | Today |
   |---|---|---|
   | `header.languages` | A `language` | `required` (warning only) |
   | `government` | B `country` | `required` (warning only) |
   | `absCNA` | C `absCNAId` | `required` (warning only) |
   | `title` | D `permitEquivalent` | **optional** |
   | `dateOfIssuance` | E | `required` (warning only) |
   | `providers` / `entitiesToWhomPICGranted` | G–N / P–W | blocking via `validateContact` |
   | `picGranted` | O `pic.consent` | **optional** |
   | `matEstablished` | X | **optional** (the ticket) |
   | `subjectMatter` | Y | `required` (warning only) |
   | `usages` | AC `usage` | `required` (warning only) |

   Conditional rules in the form (`*Confidential` checkboxes) are already
   expressible in Excel only for provider/pic/usage, via the literal value
   `confidential`; that value is non-blank, so a blank-check covers it.
   `subjectMatter` has no confidential option in Excel, so it is always required.
3. `Schema.parseTextToBoolean` returns `false` for anything but `yes`, so a
   blank MAT cell currently silently becomes "not established".

## Approach

1. `ircc/attributes-map.ts`: add `required: true` to `permitEquivalent` (D),
   `matEstablished` (X) and `pic.consent` (O) so the `*` header marker matches
   the form.
2. `ircc/index.ts`: add `validateRequiredFields(row, rowIndex)` that walks the
   flattened `attributesMap` (top-level and nested) for entries with
   `required: true`, **excluding** the contact sub-fields (none are flagged
   `required`, so `pic.consent` is the only nested hit) and emits
   `{ level: 'error', message: 'This field is required' }` for blank values via
   `Schema.isEmpty`. Call it from `validateRows` per row. This makes every
   `required` column blocking, not just MAT — required by "behave like the form".
3. Accepted MAT / consent values stay `Yes` / `No` (case-insensitive);
   `parseTextToBoolean` is unchanged. Invalid non-blank values (e.g. "maybe")
   are out of scope.
4. Message text reuses the existing `'This field is required'` string.

## Tests

No vitest in the repo yet (see AGENTS.md); verify manually in the browser with
crafted rows (copy of the en template):
- MAT (X) blank → blocking error on that cell, Import disabled; `Yes`/`No` → ok.
- D blank, O blank → blocking errors.
- language/country/CNA/issuance date/subject matter/usage blank → now blocking.
- `confidential` in provider type / PIC type / usage → still accepted.
- Fully valid row → no errors.

## Risks / open items

- **Behavior change:** blank `language`/`country`/etc. previously imported with
  a warning; now blocked. Intended (matches form) — call out in the PR.
- A blank required cell will show both the existing read-excel-file *warning*
  and the new *error* for the same cell (duplicate list entries; error wins on
  the cell). Check in the browser; if noisy, filter the warning in
  `validateRows`' output or in `read-sheet.ts` (shared with other doc types —
  avoid changing unless needed).
- The `.xlsx` templates (`app/assets/bulk-import/ircc-template-*.xlsx`) may
  mark required columns in their own header text; not editable here — check
  manually and flag to the ticket owner if MAT/D/O need a marker.
- No ADR/CONTEXT.md contradiction found (hybrid layer untouched).

## Acceptance criteria

- A row with blank MAT, permit reference or PIC consent cannot be imported.
- Every field the edit form requires is a blocking error when blank in Excel.
- `yarn lint` and `yarn typecheck` pass.
