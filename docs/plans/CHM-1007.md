# CHM-1007: Bulk import: replace overlay dialogs with proper Bootstrap 5 modal dialogs

> Type: New Feature · Jira status when planned: In Review · Component: ABSCH
> Branch: `blaise/feat/CHM-1007-bs5-bulk-import-dialogs` (off `origin/master`)
> Must land before CHM-1006 (submit-for-review option in the done dialog), which
> builds on the markup produced here.
> Design settled in the grilling session (2026-11-09); decisions below are final.

## Intent

`bulk-import-done-dialog.vue` and `bulk-import-confirm-dialog.vue` render as
`position-absolute` overlay `<div>`s with a white wash inside the import modal —
not real BS5 modals like the rest of the app. Convert both to BS5 modal markup
with a header, body and footer.

## Findings

- Both components are rendered **inside** the parent's `.modal-content`
  (`bulk-import-modal.vue:116-149`), which is itself hand-rolled
  (`modal show d-block` + a sibling `modal-backdrop show`; no Bootstrap JS).
- The parent `.modal` (z-index 1055) creates its own stacking context. A child
  `.modal` + `.modal-backdrop` rendered inside it are stacked relative to each
  other within that context, above the parent's normal content, so the stock
  BS5 z-indexes (backdrop 1050 < modal 1055) are enough. No z-index override is
  needed, but **verify visually** (fixed children are not clipped by the
  parent's `overflow-hidden` unless an ancestor has a `transform`; none does
  because the parent has no `.fade`).
- `common/modal.vue` uses Bootstrap's JS `Modal`, which does not stack well on
  top of an existing modal — rejected in the design; do not use it.
- Vue is 3.4.19: no `useId`, so use fixed `aria-labelledby` ids per component
  (only one instance of each is ever visible at a time).
- `app/app-text/components/bulk-import/bulk-import-modal.json` is a flat-key
  English source; the build wraps it per locale, so adding English keys there
  is the whole "English-only for now" step.

## Approach

1. `components/bulk-import-done-dialog.vue` — one root `<div>` containing
   `<div class="modal d-block" tabindex="-1" role="dialog" aria-modal="true"
   aria-labelledby="bi-done-title" @keydown.esc="emit('onClose')">` →
   `modal-dialog modal-dialog-centered` → `modal-content` with:
   - `modal-header`: `<h5 id="bi-done-title" class="modal-title">` = existing
     `bulkImport.importSuccess`; no X button.
   - `modal-body`: the `message` prop.
   - `modal-footer`: primary Close button (`bulkImport.close`), focused on
     mount via a template ref.
   followed by `<div class="modal-backdrop show" />`. No click handler on the
   backdrop or the `.modal` (backdrop click does nothing).
2. `components/bulk-import-confirm-dialog.vue` — same structure with
   `aria-labelledby="bi-confirm-title"`; header shows the new **`title` prop**;
   body shows `message` + the existing default slot; footer has Cancel
   (`btn-secondary`, `bulkImport.cancel`) and the confirm button
   (`confirmClass`/`confirmLabel` unchanged). Esc → `onCancel`. Focus the confirm
   button on mount for the confirm-import case only if it is the primary action;
   for the destructive close/erase cases focus Cancel (safer default). Decide via
   the existing `confirmClass` (`btn-danger` → focus Cancel, else focus confirm).
3. `bulk-import-modal.vue`: pass the new `title` prop to the three
   `BulkImportConfirmDialog` usages; no other change. All other props and emits
   on both components stay identical — **the one exception is the added
   `title` prop on the confirm dialog**, required by "confirm dialogs get a
   header with a title".
4. `bulk-import-modal.json`: add three flat English keys:
   `confirmImportTitle` "Confirm import", `confirmCloseTitle` "Discard changes?",
   `confirmEraseTitle` "Erase data?". No fallback text inline in `t()` calls
   (repo convention); other locales come later.
5. Remove the old overlay classes/inline `style` from both components; keep
   nothing that becomes unused. Pre-existing inline fallbacks
   (`t('bulkImport.cancel', 'Cancel')`) in untouched code stay as they are.

## Out of scope

Other overlay-style dialogs elsewhere in the app; translations for non-English
locales; changing the import flow or the parent modal's markup.

## Verification (manual — no vitest in the repo)

In the browser, with a built bundle:
1. Pick a valid file → "Create draft records" → **confirm import** dialog: header
   "Confirm import", draft/linked counts in the body, Cancel + Confirm; Esc
   cancels; clicking the dim backdrop does nothing.
2. Close the import modal with data loaded → **discard** dialog (destructive
   styling, Cancel focused); Esc cancels; "Yes, close" closes.
3. "Clear list" → **erase** dialog, same checks.
4. Finish an import → **done** dialog: header "Import successful", message
   body, Close focused; Esc and Close both dismiss and emit `onImported` as
   before.
5. Each dialog dims the import modal behind it, is centered, and is not clipped.
6. `yarn lint` and `yarn typecheck` pass.

## Risks

- Stacking/clipping of fixed-position children inside the hand-rolled parent
  (see Findings) — the one thing that could need a `z-index` tweak; checked in
  step 5 above.
- The added `title` prop is a (small) interface change to the confirm dialog,
  contrary to "props unchanged" in the grilling summary; flagged here so it is
  an explicit decision, not a silent one.

## Acceptance criteria

- Both dialogs are real BS5 modals with header, body and footer, and match the
  app's other dialogs visually.
- Backdrop click does nothing; Esc = Cancel/Close; focus lands on a sensible
  button; `role="dialog"`, `aria-modal` and `aria-labelledby` are set.
- All existing import-flow behavior is unchanged.
